# Pocket Hustle, Plan 2 of 3: Screens and Sound on the PC Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The real game, `pocket-hustle`, playable on the PC: every screen from the approved mockups drawn at 320 x 240 and doubled to 640 x 480, driven by buttons (keyboard on the PC) with the mouse as an extra, original sound effects, autosave and resume, and high scores.

**Architecture:** Three new platform-free layers on top of the Plan 1 core. `src/gfx` draws into a 320 x 240 canvas (primitives, the Press Start 2P bitmap font, icons, sprites, the seven skylines). `src/sfx` synthesizes sfxr-style effects and mixes them. `src/ui` is the screen state machine: it reads the `Game`, calls only the core's public API, queues sounds, and persists through an `App` object. `src/plat` (SDL2) and `src/app/main.c` are the only code that touches the OS; Plan 3 adds the Miyoo platform next to `plat_sdl.c`. Tests drive `src/ui` headless with button presses and inspect the game, the screen and the canvas.

**Tech Stack:** C99, GNU make, SDL2 (2.32 on the dev PC, through `pkg-config sdl2`), Python 3 with PIL for the one-time font conversion and screenshot export, the `gta1-miyoo-toolchain` Docker image for the ARM compile check.

**Spec:** `docs/superpowers/specs/2026-11-06-pocket-hustle-design.md` (approved 2026-11-06; bank fee and mockup decisions added 2026-11-07). **Visual source:** `docs/mockups/screens-round1.html` (approved by Seth 2026-11-07: "Font is great, look is good"). Its drawing code is the reference for every screen in this plan.

## Global Constraints

- Everything in Plan 1's Global Constraints still holds: repo, commit identity and co-author line, MIT license, no em or en dashes anywhere (`scripts/check-copy.sh`), printable ASCII for player-visible strings, the Beermat denylist, no Beermat files, integer-only `src/core` and `src/content`.
- Screen: a 320 x 240 canvas of XRGB8888 pixels, doubled to a 640 x 480 framebuffer. Every screen fits with no scrolling. Every action is reachable with buttons alone; the mouse is optional and PC-only.
- Font: Press Start 2P (SIL Open Font License 1.1), 8 x 8 cells, 10-pixel lines. The TTF and `OFL.txt` live in `assets/fonts/`, and the README credits it. No other outside assets.
- Look: the palette, layouts, icons, sprites and skylines of `docs/mockups/screens-round1.html`. Each per-screen question still open in the mockup keeps the mockup's behavior unless Seth answers it.
- Controls (spec table): D-pad moves the highlight, A selects or confirms, B goes back, L1/R1 jump between panels, the amount picker steps 1 on up/down and 10 on left/right with Y = max and X = zero, SELECT opens the price chart, START opens the pause menu. Money amounts use the digit dial from the mockup.
- PC keys: arrows = D-pad, Enter or Space = A, Esc or Backspace = B, Tab = R1, Shift+Tab = L1, `]` = R1, `[` = L1, Y = Y, X = X, C = SELECT, M = START, F11 or Alt+Enter = fullscreen. The mouse clicks anything that has a hit region.
- No `float` or `double` in `src/gfx` or `src/ui`, so screens render pixel-identical everywhere. Trig comes from the committed integer table (`isin`/`icos`). Floats are allowed in `src/sfx` and `src/plat` only.
- `src/gfx`, `src/sfx` and `src/ui` include no SDL or OS headers beyond the C library. Only `src/plat` and `src/app` link SDL2.
- The UI never writes `Game` fields. Every change goes through the core API (`game_buy`, `game_deposit`, `game_chase` and the rest), so the rules stay in one place.
- Persistence (same policy as ph-text): save when the day or the phase changes, on SAVE AND QUIT and when the window closes; record the high score and delete the save exactly once when the game ends. Data directory: `--data DIR`, else `$XDG_DATA_HOME/pocket-hustle`, else `$HOME/.local/share/pocket-hustle`. Files: `save.dat`, `scores.dat`, `options.txt`.
- Sound effects only (no music), all generated by our synth from parameter presets.
- Input is drawn in the same loop iteration it arrives: the loop redraws on any input and on every 50 ms tick.
- `make test` stays one command: unit tests, golden transcript, copy check. New test modules are listed in `tests/tests.h` and `MODULES[]` in `tests/run_tests.c`.

## Review Focus

1. **Extreme values on screen:** cash, bank and debt near `MONEY_MAX`, a negative net worth, a 15-character name, the longest lender, hood and gear names. Nothing is drawn off the canvas and nothing overlaps its neighbor column. (Task 12: every screen drawn from an extreme state with the canvas overflow counter at zero.)
2. **Power-off or window close in the middle of a flow** (picker open, news half read, mid-chase): on the next launch Continue lands on a consistent screen for the saved phase, never a half-open picker. (Tasks 10 and 11: resume into a chase; close-window save.)
3. **Holding a button:** the D-pad and the picker auto-repeat (first repeat at 300 ms, then every 80 ms); A, B and the shoulders never repeat; a held picker stops at max with no overshoot. (Tasks 5 and 12.)
4. **Mouse clicks on overlays:** a click only reaches the topmost screen's regions; a click outside every region does nothing; a click during the news advances exactly one card. (Tasks 6, 7 and 12.)
5. **Every way a game ends** (moving on the last day, goons killing you on arrival, dying in a chase, jail on the last day, END GAME NOW) shows the game-over screen, records exactly one high score and deletes the save. (Tasks 7, 10 and 11.)

## Decisions made in this plan (Seth can overrule)

- The title menu gets a fourth item, QUIT, because on the Mini it is the way back to OnionOS. The mockup had three.
- Closing the window saves like SAVE AND QUIT, so the PC never loses a day's trades.
- The price chart shades each good's base range (the core does not record which city a price came from) and colors points above it pink and below it green.
- Airport codes (OKC, IAH, SJC, JFK, MIA, MSY, PDX) become content: a `code` field on `CityDef`, linted like other content.
- A sound option (on or off) is the only option for now, stored in `options.txt`.

  typedef enum { SFX_MOVE, SFX_OK, SFX_BACK, SFX_DENY, SFX_CASH, SFX_HURT, SFX_SIREN, SFX_NEWS, NUM_SFX } SfxId;
  typedef enum { WAVE_SQUARE, WAVE_SAW, WAVE_SINE, WAVE_NOISE } Wave;
  typedef struct {
  	Wave wave;
  	float freq, slide, slide_accel;		/* Hz, Hz per second, Hz per second squared */

  void mixer_fill(Mixer *m, int16_t *stereo, int frames);	/* saturating; zeros when muted */
